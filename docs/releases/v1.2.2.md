# MediaOps v1.2.2 — Runtime Compatibility Fixes

MediaOps 1.2.2 is a corrective patch release for runtime compatibility issues discovered after v1.2.1 and verified on the hardened deployment path.

## Fixed

- **Jellyfin 12 API authentication:** valid Jellyfin API keys could return HTTP 401 because MediaOps used the deprecated `X-Emby-Token` authorization mechanism. MediaOps now sends the supported MediaBrowser Authorization header.
- **Discord Router on hardened containers:** Gunicorn 26 could attempt to create `/.gunicorn` and log a read-only-filesystem control-server error on Unraid and ADM. The unused Gunicorn control socket is now disabled while keeping the root filesystem read-only.
- **Router health endpoint:** the companion Router now exposes `GET /health` for local/container health checks without contacting Discord or a request provider.

## Validation

- MediaOps typecheck, automated tests, application build, npm production dependency audit, Router Python dependency audit, Router syntax validation, and Router Docker build pass in CI.
- The Router is smoke-tested in CI with a read-only root filesystem and writable tmpfs paths; startup must succeed without a Gunicorn control-server error.
- Jellyfin 12.1.0 connectivity was validated with the updated MediaBrowser authorization flow.
- Seerr request-provider operation and Router startup were validated on the hardened ADM deployment path.

## Hardening retained

The Router remains non-root, read-only, capability-dropped, protected by `no-new-privileges`, and compatible with the existing hardened deployment model. No secret-handling behavior is relaxed.

## Upgrade

Update both MediaOps and the companion Router to v1.2.2/latest. Existing valid Jellyfin API keys and provider configuration can be retained; no credential regeneration or configuration migration is required.

For Docker deployments, update both images together:

- `ghcr.io/miakkia/mediaops:latest`
- `ghcr.io/miakkia/mediaops-ombi-discord-router:latest`
