# MediaOps v1.2.1 — Security Maintenance

Released: 2026-09-15

MediaOps v1.2.1 is a patch release focused on security maintenance, safer container defaults, dependency refreshes, and clearer provider webhook protection. Existing Emby + Ombi installations remain supported and the webhook authentication feature is backward-compatible by default.

## What changed

- MediaOps runtime updated to Node 24 LTS.
- MediaOps Discord Router pinned to Python 3.13.15.
- Router dependencies refreshed to Flask 3.1.3, Requests 2.34.2, urllib3 2.7+ and Gunicorn 26.2.0.
- Router now explicitly runs as unprivileged UID/GID 1000:1000.
- Hardened examples use a read-only root filesystem, dropped Linux capabilities, `no-new-privileges`, a 256 MiB memory limit and a 64 PID limit.
- Provider webhook request bodies are limited to 256 KiB by default.
- Optional per-provider webhook authentication was added with `off`, `optional`, and `required` modes.
- Authentication secrets are compared in constant time and are intended for headers, not query strings.
- CI now audits both production Node dependencies and Router Python dependencies for known vulnerabilities.
- Jellyfin and Seerr provider support introduced in the current 1.2.x development line is included in this maintenance release.

## Ombi users

No authentication change is required after upgrading. Ombi does not natively supply the custom header used by the Router authentication mechanism, so the recommended configuration is to keep Ombi and the Router on the same private Docker network and leave:

```env
OMBI_WEBHOOK_AUTH=off
OMBI_WEBHOOK_TOKEN=
```

Do not expose Router port 8080 directly to the Internet.

## Seerr users

The Router can validate a shared webhook secret when the webhook path can send the configured custom header. A safe migration is:

1. Generate a long random secret.
2. Configure the same secret on both sides.
3. Start with `SEERR_WEBHOOK_AUTH=optional`.
4. Send a test webhook and verify normal Router processing.
5. Switch to `SEERR_WEBHOOK_AUTH=required` only after successful validation.

The default header is `X-MediaOps-Webhook-Token`. Never put the secret in the webhook URL.

## Compatibility

Existing provider webhooks continue working after the image update because authentication defaults to `off`. No provider migration is required. The historical `mediaops-ombi-discord-router` image/path remains in place for upgrade compatibility even though the component is now documented as MediaOps Discord Router.

## Verification

The release preparation passed MediaOps typechecking, the existing 100-test suite, application build, Router syntax/build checks, production `npm audit`, and Python `pip-audit` during the security maintenance work.

## Known scope

Jellyfin SyncPlay orchestration and Plex support are not included yet. Emby Watch Party remains the current Watch Party implementation.
