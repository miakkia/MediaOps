# Code of Conduct

MediaOps is intended to be a welcoming, technical, and constructive open-source project for self-hosters, homelab enthusiasts, media-server administrators, and contributors of all experience levels.

## Our standards

Participants are expected to:

- communicate respectfully and professionally;
- focus criticism on ideas, code, documentation, and technical decisions rather than individuals;
- assume good intent while still raising security, reliability, or quality concerns clearly;
- provide enough context when reporting bugs or proposing changes;
- respect different levels of technical experience;
- avoid harassment, discrimination, personal attacks, intimidation, or hostile behavior;
- avoid spam, trolling, deliberate disruption, and off-topic promotion;
- protect private information and never publish credentials, tokens, API keys, private logs, or personal data belonging to others.

## Technical discussions

Disagreement is normal in engineering. Contributors may challenge an implementation, architecture decision, dependency, or product direction, but discussion should remain evidence-based and useful to the project.

Good technical feedback should explain the concern, the expected impact, and—when practical—a safer or simpler alternative.

MediaOps follows a simplicity-first philosophy. More complex solutions should justify the operational or product value they add.

## Security-sensitive content

Do not post active secrets, private endpoints, authentication material, or exploit details that would unnecessarily expose a user's infrastructure.

Potential security vulnerabilities should follow the process described in `SECURITY.md` rather than being disclosed publicly when doing so could put users at risk.

## Scope

This Code of Conduct applies to MediaOps project spaces, including:

- GitHub issues;
- pull requests and code reviews;
- discussions;
- documentation contributions;
- project-related community channels;
- other spaces where someone is representing the MediaOps project.

## Unacceptable behavior

Examples of unacceptable behavior include:

- harassment or discriminatory language;
- threats or intimidation;
- repeated personal attacks;
- publishing another person's private information without permission;
- intentionally introducing malicious code or hidden credential collection;
- knowingly encouraging insecure handling of secrets;
- sustained disruption of technical discussions after being asked to stop.

## Enforcement

Project maintainers may edit, remove, reject, or lock contributions or discussions that violate these standards. Repeated or serious violations may result in temporary or permanent restrictions from project spaces.

Enforcement decisions should be proportionate to the behavior and focused on keeping the project safe and productive.

## Reporting concerns

For ordinary conduct concerns, contact the project maintainer through an appropriate private channel when possible.

For security vulnerabilities or accidental credential exposure, follow `SECURITY.md` and avoid unnecessary public disclosure.

## Project principle

MediaOps should be a place where people can build, learn, question decisions, and improve the software without needing to tolerate hostility or careless security practices.
